OBJECTIVE (candidate target architecture, only if justified by step 1)
 Writer A — Intake: new jobs, deduplication, application-state protection, canonical identity creation.
 Writer B — Enrichment: updates to EXISTING records only, addressed by canonical PRIMARY_ID; never creates identities.
 Shared transaction coordinator: one locking/version authority, idempotent request IDs, durable receipts,
   receipt-index reconciliation and exact readbacks for both Writers.
 Both Writers operate on the SAME canonical master. No copies, no second master, no second receipt ledger.

HARD CONSTRAINT
 Two Writers must never modify the master without coordinated locking and a single transaction authority; otherwise
 duplicates, lost updates and corrupted receipt reconciliation follow. Today the Writer's saveMasterLines_ relies on
 one script lock, a single-pending-transaction write fence in the receipt index, and a pre-commit snapshot hash —
 any second write path must participate in exactly that protocol (or its replacement) before it writes anything.
