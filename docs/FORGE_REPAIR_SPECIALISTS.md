# Reusable Forge repair specialists

These are callable procedures for Dot, ChatGPT Work and Codex. They do not create agents, schedules, permissions or native task bindings. Read current main, repository instructions and the registered owner procedure before using one. If the interface supports delegation, give the specialist a bounded case and this procedure; otherwise perform that role directly. Do not claim an unavailable delegation happened.

Each invocation needs an exact case/source version, current symptoms, existing evidence and the specific question to resolve. Return the observed cause and evidence, actions actually attempted, result, relevant checks, and the next executable step. Distinguish proposed repair, published evidence, deployed behavior and independently verified canonical effects. Continue unrelated cases on exceptions. A proposed owner or retry condition alone is not progress.

## Automation configuration and routing

Compare `control/AI_AUTOMATION_TASKS.json`, `control/NATIVE_AUTOMATION_BINDINGS.json`, current procedure, actual installed configuration and invocation evidence. Separate local/cloud inventory, service work, task work and native launch proof. Check duplicates, disabled replacements, destinations and scope. Unavailable local configuration is unverified, not proof of failure. Prepare configuration/code corrections for review; preserve active scheduling and destination ownership unless explicitly authorized to change them.

Read `tools/automation-health/` and `docs/PIPELINE_RECOVERY_CONTRACTS.md`. Validate corrections against the native inventory, generated catalogue and relevant automation-health tests. Finish with the observed binding mismatch and verified correction or the exact missing observation.

Apply current Never Consider rules with supplier protections. Do not invent ATS scores, pay, credentials or resume conclusions.

Confirm actual file names in current main before execution. Return supported exact-job facts through the existing evidence transport; canonical persistence remains owned by the coordinator/Writer.

Distinguish validity at artifact creation from current eligibility at consumption. Validate immutable source hashes, original assignment membership, instruction provenance and exact identity. Current protected decisions, fences and missing fields remain controlling. Isolate malformed siblings instead of dropping valid artifacts. Interview/correspondence revisions need exact source/event identity and chronological precedence; an ambiguous newer interpretation does not silently supersede established history.

Read `tools/routine-handoffs/`, `tools/helper-routing/` and `lanes/CHATGPT_APPLICATION_OUTCOME_TRACKER.txt`. Use the existing inspection/correction transport. ## Queue progress and exception recovery

Read `node tools/routine-handoffs/exceptions.cjs <checkout>` and the current START/CHECKPOINT progress before selecting work. Respect selections already being worked by the registered tracker. Rotate exception classes using the existing selection order; resume interrupted accounting from actual immutable evidence. Listing/capture is zero review progress. Attempt a concrete permitted recovery step and re-read its outcome. An access problem on one case does not stop independent cases.

The registered tracker owns `start`, `review` and `checkpoint`; follow its current procedure and actual task identity when publishing those artifacts. Dot does not impersonate it. Return source-bound findings through an already authorized transport, or prepare a focused repair PR. Resolution requires independent consumption/effects; repeated zero-progress cycles need a specific diagnosis and next action.

## Writer contention and reconciliation

Classify accepted, request-bound NOT_ACCEPTED and unknown outcomes separately using `tools/writer-outcome.cjs` and `reference/WRITER_OUTCOME_CONTRACT.json`. A known refusal may use its existing bounded retry path. Unknown originals require receipt/result reconciliation and exact effects; absence or an unreadable response never authorizes replay. Respect protected decisions, source identity, transaction fences and retry-after. Preserve the original deployed-source witness when needed.

Read coordinator transactions and the public recovery contract. Keep full responses, row snapshots, correspondence and credentials private; public proofs use the existing allowlisted projections and original/projection hashes. Do not manufacture canonical proof from a prepared review, HTTP success or a saved audit. Dot prepares evidence/code repairs; existing authorized workers perform canonical writes.

## Job-alert extraction and source recovery

Reuse saved full MIME/card evidence before new searches. Account separately for proven mailbox enumeration and semantic disposition; truncated or unreadable bodies stay pending. Preserve each card's employer/title/location/provider ID/exact URL without borrowing a neighbor's fields. Opaque links with known facts become existing source-recovery work, not invented IDs. Partial failures must retain valid neighboring cards and unresolved coverage.

Read `docs/ALERT_SOURCE_CAPTURE.md`, `tools/routine-handoffs/mail-content.cjs` and the actual extractors in current main. Confirm file locations before use. Return immutable evidence through the registered mail/intake transport. Verify downstream consumption rather than counting captured cards as canonical jobs.
