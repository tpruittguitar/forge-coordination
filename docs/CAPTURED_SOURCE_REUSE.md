# Captured source reuse and remaining controls

Tim's November 11 direction is to use JobSpy, HiringCafe, LinkedIn, recruiting and employer job text equally, and remove source-verification steps that unnecessarily stop identified jobs reaching intake. This is a source-evidence change, not permission to replay Writer requests or change protected decisions.

## Removed duplicate requirements

- AUTO no longer requires a second employer-page business description when a bound saved card or description already identifies the lead. Missing business/requirements stay unknown.
- Intake reads the current saved report as well as immutable text, catch-up and upstream artifacts. It does not wait for asynchronous cache publication.
- Aggregator origin does not make an otherwise complete description partial. Explicit partial flags, selected excerpts and challenge pages remain correctly labeled.
- Six-hour intake, seven-day retained-text and 24-hour helper/positive-review age limits no longer force a duplicate source fetch. The original capture date remains unchanged. Explicit posting expiry is distinct from age.
- Obsolete SOURCE_EVIDENCE_UNAVAILABLE retries release when bound captured details exist. Historical attempts are retained, without claiming admission.
- Programmed helper intake, source verification, seeding, preparation and assignment routing use the same captured facts before outside research. SOURCE_CAPTURED does not mean independently fetched or currently live.
- Ordinary intake does not require helper fit/quotation assertions when it is using the repository's actual recorded facts. Enrichment and genuine quoted-scope reconciliation still validate any fields they claim.
- Optional description text returned by HiringCafe is preserved, rather than dropped while retaining only metadata.

## Controls retained and why

- Current authenticated canonical identity/protected-state reads and current rules remain necessary because other workers and Tim can change a job's state. Source text age is not canonical-state freshness.
- Known employer, title, requisition, worksite, source-URL or canonical-ID conflicts remain explicit. A country-wide location stays country-wide; it is not invented as a precise site.
- Existing title/function and current grounded ATS/business exclusions remain. Missing or partial text cannot establish absent requirements.
- Exact quotes and current resume support are required only for the specific fit/qualification claims being written. Unsupported helper-derived numbers and fields are not imported.
- Site-estimated salary stays estimated. Unsupported currency, annual period or base/total basis does not become employer-posted annual USD base pay. Salary-model handling and common-instruction alignment are coordinated in the separate salary change.
- Explicit expired postings, genuine official-business exclusion review and unresolved identity/scope obligations retain their own targeted evidence checks. Inaccessible pages alone do not invalidate already captured usable facts.
- Richer old text cannot hide a later explicit expiry or extension for the same identity and posting. The text and expiry retain separate original dates and proofs. A malformed expiry or conflicting requisition holds only that card; healthy siblings continue without a legacy verified-evidence fallback. Compatible requisition aliases remain usable.
- Active assignments, Writer release/freeze/lock controls, durable intent and receipt recording, original request IDs, uncertain-result fences and exact post-write verification remain. Captured evidence cannot bypass them through catch-up.
- Retired manual helper and dry-run admission prototypes retain their old contracts; they have no active execution caller. This change does not reactivate them.
