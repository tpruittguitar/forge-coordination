# Programmed coordinator

Routine coordination now has a local Node entry point: `node tools/programmed-coordinator/run.cjs apply`. It collects published helper returns, validates current assignments, reuses source evidence, prepares intake through the existing relevance screen, drains successive Writer transactions, verifies exact effects, and publishes accounting for the existing dashboard observer. It introduces no WIP, daily, job-count, or transaction-count processing cap. A 100-record intake transaction and a 25-record maximum enrichment envelope are payload boundaries.

`inventory` requires no Writer credential and reads published batches only. `preview` additionally reads authenticated current master/archive and inspects supported public structured postings, saving its report and source bodies privately without submitting or changing repository state. `apply` requires clean, freshly resolved merged main, the existing local Writer connection, the current shared production lock, and a private directory outside this public repository.

## Direct processing of returned evidence

`node tools/programmed-coordinator/run.cjs apply --returns-only` consumes existing captured Drive artifacts and configured local helper inboxes, validates their immutable envelopes and current assignments, and writes supported details through the current Writer. No routine user approval, manual receipt PR, second AI review, or full mail/intake sweep is required between valid evidence and its Writer transaction. Helpers retain `writerSubmitted=false`: only the trusted local adapter submits, using the existing private connection. This is not a new provider-facing endpoint and gives no helper Writer credentials.

Use `--batch receipts/<supported-helper-path>.json` to select one exact return; repeat that flag for multiple returns. Without it, all supported returned evidence is eligible. A selected missing, legacy-tracked, or quarantined batch is an explicit exception, not a successful empty run. Registered shared, Claude, intake, enrichment and relevance helper envelopes are supported. Intake-drain reviews retain their existing source-intake-auto path; private outcome batches retain authenticated mail/event reconciliation. Retired/disabled routes stay retired/disabled.

The normal scheduled `apply` path now processes returned enrichment immediately after transport collection and original-request reconciliation, before unrelated mail, interview work, assignment replenishment and intake. No schedule change or new provider callback is needed for that ordering. It refreshes canonical state after new transactions before downstream work.

The optional returns-only mode also skips browser polling, email enumeration, interview work and assignment replenishment. It submits independently verified enrichment before intake. Intake preparation and selection are restricted to the returned keys, while unrelated plan entries, pending originals, source state and the full coordinator ledger remain intact. Every write uses the same live identity/protection checks, shared lock, immutable pre-POST checkpoint, single-send handling, duplicate/request fences, independently COMPLETE receipt and exact canonical readback. Unsupported facts or inaccessible sources remain explicit exceptions. Existing supported source extraction remains the boundary; arbitrary proposed fields never become Writer payloads.

The only compatible registry migration is `EVIDENCE_ONLY` to `WRITE_THROUGH_SUPPORTED_WRITER` for the named non-retired job-helper routes, with unchanged owner, procedure, assignment path and current work ownership. Historical evidence still must say it was not submitted, and current policy/source checks always run. This preserves real returns captured before the instruction update without restoring retired work or expanding a helper's authority.

After merge, invoke the existing wrapper with `pwsh -NoProfile -File tools/programmed-coordinator/launch.ps1 -ConfigFile <existing-private-config> -ReturnsOnly`, optionally adding `-Batch <exact-return-path>`. It requires clean, freshly resolved merged main and retains the existing lock through accounting publication. A held lock defers the run without expiring it or canceling the owner. `inventory` and `preview` accept the same Node flags; preview reads published returns without importing new private captures or submitting writes. This change does not install, enable or modify any schedule, create a credential, or verify provider access. Existing provider transport capture and the existing full coordinator remain the automatic collector. Captures arriving after a run's collection phase are picked up on its next scheduled pass; a supported producer/transport may invoke the returns-only wrapper sooner when the current lock is free. This does not claim a new provider-side callback or immediate delivery where no supported trigger exists.

`state/DIRECT_RETURN_TRANSPORT.json` records private-artifact import accounting. The normal coordinator ledger and receipts remain authoritative for canonical effects. Only current returned shared reservations are settled after processing; no new assignments are created, and incomplete enrichment is labeled partial rather than full completion.

## Bounded helper throughput

Returned enrichment drains successive envelopes of up to **25 distinct canonical rows** through the Writer's existing multi-row single-commit path. This replaces the caller's previous one-row envelope; it does not impose a 25-row per-run quota. For example, 61 ready rows use 25/25/11 envelopes. Helper return artifact sizes remain transport page boundaries, not run limits. Source gates, current assignments, row protection and supported-field evidence still determine actual useful output; larger envelopes do not make blocked sources into completed research.

Each envelope uses one fresh canonical snapshot and validates every item independently before POST. An invalid identity, protected decision, old original-request fence, unsupported field or current evidence conflict excludes only that item. Duplicate canonical IDs never share an envelope. Uncertain sends remain attached to their immutable original transaction and are never split or replayed. Independent later envelopes continue; the live Writer gate stops submission.

Successful children of a partially held batch can receive their own immutable verification proof only after the exact original result, independent COMPLETE receipt bound to the same write ID, and later exact row effects all agree. The parent transaction remains pending until every child is verified. Its original fence is retained, unresolved siblings remain explicit, and field updates do not claim a fully enriched job. The prior single-row proof contract is unchanged.

Source HTTP 403/429 pauses now carry the actual host retry time into item scheduling rather than automatically expanding a 15-minute pause into six hours. A narrow retry-policy migration reevaluates existing source-backoff/403/429 items once, while still obeying the host pause. It does not reset identity ambiguities or original transactions. No request runs before the saved pause expires, and repeated calls during the pause do not fetch or spin.

Validation includes 61-row batching, per-item preflight isolation, uncertain sends and restart, partial successful siblings, late COMPLETE receipts, exact proof failures, duplicate IDs, global gates, selection scope, and host-backoff migration. No schedule, credential, merge or deployment change is part of this implementation.

## Durable behavior

- `state/PROGRAMMED_COORDINATOR.json` binds each immutable batch hash, item version, source inspection, exception, request ID, and transaction state. Historical Claude consumption stays in its existing ledger and is processed by the existing intake preparation; old preparation is not repeated.
- Instruction revisions may differ because of receipt commits or wording updates. Changes to task ownership, assignment, activation, retained thread partition, or cutover reject the return. Current policy always rechecks source facts. Invalid envelopes are quarantined intact, including the exact keys with missing URLs.
- Unchanged ambiguous items retain their lookup count and stay under the same durable AI exception; code does not research them again. Access failures remain code/source-route exceptions and retry after six hours, respecting route backoff and Retry-After. An unrelated case continues.
- Reuse identity-bound captured job details before fetching a posting. JobSpy, HiringCafe, LinkedIn, recruiter and employer descriptions carry equal weight; provider origin and capture age do not require another lookup. Source capture keeps its original date and does not prove liveness. Metadata-only leads may enter intake with business/requirements unknown. Partial text remains partial. Exact identity conflicts, unsupported asserted quotes and explicit posting expiry remain targeted exceptions; an inaccessible source is not a whole-job blocker when sufficient recorded details already exist. The structured-page parser remains a fallback for facts not captured.
- Helper `proposedRawFields` are never Writer payloads. Positive degree evidence is derived from the bound captured or fetched posting. Annual USD base pay needs explicit supported units and basis, irrespective of provider; site estimates remain estimated and are separate model inputs. Missing or conflicting evidence is preserved. Existing salary estimation, company/product references, scoring and ATS workers continue unchanged. Writer still calculates final scores.
- Payload and public request checkpoint are flushed before the single POST. A timeout stays `POST_IN_FLIGHT_UNKNOWN`; the original request is never replayed. The original acceptance, independently COMPLETE child receipts bound to the same write ID, and later exact canonical fields are required for verification. A zero-write result requires exact existing effects. A missing original acceptance stays a recovery obligation because the current read endpoint supplies receipts, not the retained response body.
- Existing pending intake requests are reconciled before rebuilding its plan. If their original private artifacts are unavailable, the plan remains intact. Current Writer gates and row/decision protection remain authoritative.
- New enrichment receipts feed the existing independently sourced Writer activity and process-flow dashboard. `state/PROGRAMMED_COORDINATOR_REPORT.json` additionally separates prepared items, verified updates, code exceptions, AI exceptions, and outstanding source coverage. Field updates never claim a fully enriched job.

## Local scheduled deployment after merge

Use a dedicated clean clone of merged `forge-coordination` and a current clean cockpit checkout. Keep the current private connection in its existing local location. Create a private JSON configuration outside both repositories with absolute paths for `repositoryDirectory`, `cockpitDirectory`, `connectionFile`, `privateDirectory`, and `productionLock`. The last path must match the shared lock in the current common contract. No credential value goes into this configuration, Git, or task arguments.

Run `pwsh -NoProfile -File tools/programmed-coordinator/launch.ps1 -ConfigFile <private-config-path>` once, inspect its terminal receipt and independent effects, then run `install.ps1 -ConfigFile <same-private-config-path>` from this directory. PowerShell 7 (`pwsh.exe`) is required; the installer selects that runtime rather than Windows PowerShell 5.1, which lacks the launcher's fully-qualified-path API. The installer checks merged, clean main. It registers `FORGE_PROGRAMMED_COORDINATOR` in Windows Task Scheduler every five minutes for the current signed-in user, with overlapping starts ignored and no execution-time quota. No AI tokens are needed to launch, count, validate, or poll. The PC must be available.

The launcher retains the same shared lock through publication, fetches current main, runs the coordinator, commits only its declared accounting and new receipts, rebases independent appends, pushes without force, and verifies remote ancestry. `publish.cjs` checks committed-but-unpublished accounting even when the checkout is clean, and retries a concurrent non-fast-forward push through fetch/rebase. A relevance-guard conflict is merged only when every field except `at` is identical and both timestamps are valid; the newer observation is retained. Changed policy revisions, disabled rules, unknown semantic fields, or other conflicting files remain explicit operator recovery obligations. Publication failures preserve state and unpublished commits, record private AUDIT_PENDING evidence, and release the execution lock so independent lanes continue. The next launch retries publication; Gofer reconciles unresolved accounting. It never resets a user's checkout or expires an abandoned lock. Existing GitHub observability workflows update the dashboard after receipt publication. Rollback: disable this one Windows task; retain all state and pending requests, then let the existing coordinator reconcile them. Do not delete or replay checkpoints.

## Automation retirement recommendation

No AI schedules are changed by this PR. Review configuration is not a completed replacement run, and the estimated 30–50% token savings remain unmeasured.

| Automation | Recommendation and replacement condition |
|---|---|
| `FORGE_HELPER_COORDINATOR` / `forge-email-discovery` | Remove its routine collection/validation/counter/receipt-polling work after the scheduled code run proves published-return intake, Writer effects and remote accounting. Keep an exception/source-transport run until UI-only returns, saved source pagination and assignment replenishment have working programmed adapters. Do not turn it off in full yet. |
| `FORGE_POSTING_FRESHNESS` | Retain until the current ATS checker plus a programmed non-ATS source route demonstrate the same coverage. A blocked posting is not a completed check. |
| `FORGE_APPLICATION_OUTCOME_TRACKER` and Grok outcome helper | Retain mailbox enumeration, pending-thread coverage, private source access, calendar work and ambiguous correspondence. `outcome.cjs` provides conservative standard confirmation/rejection classification, but classification alone does not persist an authenticated event or verify a Writer update. |
| Grok intake/enrichment and Claude relevance helpers | Retain research capacity for unresolved source/identity/scope exceptions. Do not reduce their assignments or throughput simply because coordination moved to code. |
| `FORGE_APPLICATION_WRITER_GOFER` | Retain its existing exception role; stop sending it routine validation or polling work. |
| `FORGE_AI_USAGE_READER`, `PE_STACK_HEALTH_DAILY` | Retain until authenticated usage readings and the complete health checks have measured code coverage. This coordinator does not replace their source access. |

Published repository returns are collected without AI. Providers exposing reports only through their native UI still need an authorized report exporter or publishing adapter; this code does not invent private APIs or claim those runs were collected. The new [routine transport and handoff modules](ROUTINE_HANDOFFS.md) implement archive/report collection, saved results pagination and non-overlapping assignment replenishment. Source-window body capture outside these saved results remains a coverage obligation. Native UI transport still requires its existing supported browser connection and observed WebMCP report tools; their current live access limitation is documented there. Their pending obligations stay visible in the existing coverage ledger. No schedule can safely be fully disabled today solely because this code exists; the immediate cut is the routine orchestration portion of the helper coordinator after rollout verification.

Validation: `node --test tools/programmed-coordinator/*.test.cjs tools/relevance-screen/*.test.cjs tools/helper-routing/*.test.cjs`. Tests cover stale routing, malformed URLs, immutable collisions, source identity/quotes, cache reuse, protected decisions, conflict rejection, pre-POST crash/restart, missing acceptance, receipt/row mismatches, zero-write accounting, independent continuation, standard email templates, and draining 2,301 items through 24 successive transactions.

## Windows publication durability

Mutable JSON saves stage unique, exclusively created sibling files, flush and close
those bytes, then atomically replace the destination. Sharing/access-busy rename
failures (`EPERM`, `EACCES`, `EBUSY`) retry the same staged bytes up to eight times
with at most 1.575 seconds of backoff. The old destination is never deleted or
truncated as a workaround. Other errors fail immediately. Persistent failures
preserve both the prior destination and the uniquely named staging file for
reconciliation, and remain explicit failures. They do not silently publish or
replay a checkpoint. Earlier `.tmp` evidence is not overwritten or auto-recovered.

The shared helper work source and all shared page/index files have explicit LF
Git attributes because their bindings hash exact bytes. Publication also compares
validated source/page bytes with Git's staged blobs before committing and after
rebase, rejecting any clean-filter or newline transformation before push. These
checks do not relax immutable hashes or regenerate historical pages. Already
stranded checkouts still require evidence-preserving reconciliation; merging this
code does not itself recover retained files or deploy it to a running coordinator.
