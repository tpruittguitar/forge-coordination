# Manual discovery backlog decisions

Pipeline Explorer submits explicit user selections to `/api/backlog-decisions`, authenticated with the existing Writer key. Each request binds up to 100 discovery identity keys, DECLINE or DELETE, and the exact coordination snapshot revision displayed. DELETE is recoverable exclusion from the active backlog, not erasure of evidence or canonical records. Remote and multi-location jobs are not inferred exclusions: only actual selected keys are considered.

Requests are immutable and content-addressed in the existing cockpit KV. The browser must persist the normalized SHA256 receipt ID before POST. After timeout or disconnect it reads that receipt; it does not replay a mutation. Queued is not removed.

The existing pipeline-observability worker reads this inbox using its existing Writer credential. No new schedule, worker identity, credential, or Writer action is introduced. The observer loads the exact hash-verified waiting-page snapshot once per selected revision, compares current identity, then checks fresh canonical master/archive and existing Writer fences. Legacy requests permit only WAITING identities with no protection or conflict. New requests explicitly bind scope=DISCOVERY_CARD_DISMISSAL into the content hash. This dismisses the exact displayed discovery card, including unresolved cards and ordinary HELD/EXISTING_PROTECTED discovery evidence, without another fit review. It never deletes a canonical record. Active or uncertain Writer operations, conflicting identity evidence, canonical references and stale cards remain protected. Canonical presence always takes priority.

The observer retains all ledger entries and proof, adds per-item receipts under receipts/manual-backlog, and publishes receipt plus reconciled ledger/counts together. Only an APPLIED result from a committed observer receipt is a completed exclusion. HELD, STALE, and ALREADY_ACCOUNTED are distinct outcomes. Existing canonical Writer ownership is unchanged. If an identity later appears in canonical state, canonical presence takes priority.

Deploy the cockpit endpoint and merge the coordination worker implementation through their normal reviewed release paths. Capabilities remain disabled until a fresh waiting-queue snapshot advertises manualDecisions.version=1. Old cockpit 404 or HTML fallback is tolerated during rollout. Other inbox failures preserve the last successful reporting component. UI publication alone cannot remove candidates; coordination publication alone cannot accept new selections.

Validation: node --test tools/manual-backlog/*.test.cjs tools/pipeline-observability/*.test.js (set ACTIVITY_FC_DIR to a foreman-cockpit checkout for aggregate tests).

Explicit selection is the user decision; no additional fit, salary, geography, or relevance approval is required. Transport accepts the discovery ledger identity families: LinkedIn numeric IDs, Indeed 16-character lowercase hexadecimal IDs, URL and unresolved 24-character lowercase hexadecimal hashes, and namespaced canonical PID references. Supported references are evaluated per item rather than rejecting unrelated selections in a mixed batch. Legacy unresolved and all canonical references retain technical protection; new dismissal-scoped unresolved cards can be dismissed. Canonical presence, identity conflicts and uncertain Writer ownership remain protected. The displayed relevance reason is not proof that a HELD entry is safe: its underlying evidence may be EXISTING_PROTECTED.

Dismissal uses the existing EXCLUDED ledger accounting, with scope-bound manual proof and receipt reason USER_DISMISSED_DISCOVERY_CARD_HISTORY_RETAINED. The saved card, source evidence and request remain available for recovery. Intake drain stops pursuing accounted cards, and source intake filters exact dismissed URL identities even when rediscovered in reports or catch-up inventory. A changed displayed identity invalidates its proof; a new active Writer fence suspends the dismissal so reconciliation cannot be hidden. Old unscoped requests keep their original hashes and stricter semantics; this change never replays or upgrades them.
