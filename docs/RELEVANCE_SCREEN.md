# Live discovery relevance screen

Tim authorized this release on 2026-11-01 after the read-only function backtest. Policy: forge-policy commit f81142fef4d864176adc8bbc7e7c3292d330c54e. Configuration: control/RELEVANCE_SCREEN.json. One shared implementation serves automatic intake, local helper consumption and discovery-flow reconciliation.

## Outcomes

- ADMIT: sourced plausible target-function leadership/strong technical card; proceed through ordinary fresh canonical, source and Writer checks. Missing salary/degree goes to enrichment.
- FUNCTION_MISMATCH: original seven proven off-function categories only, absent manufacturing context. Each closure stores source title, URL, exact term, rule and policy revision. It closes discovery only, never declines a canonical job.
- RANKED_DISCOVERY / HOLD_SOURCE_IDENTITY: remain visible in the saved plan and source queue, with a specific missing fact. Operations/GM ambiguity, lower/unclear level, missing pay, agency/client ambiguity and geography do not become terminal exclusions.

Ranking uses target function then proven source date and stable identity. It is a cheap work-order signal, not final job scoring. At most one targeted scope lookup per unclear candidate, reuse shared employer facts, save the lookup and result; unknown remains explicit. No WIP, daily admission or application quota. Transaction payload sizes, locks, platform execution boundaries and three-proof verification remain safeguards rather than capacity targets.

## Reuse and recovery

The prepare command validates immutable helper batches and matches saved full cards or a pinned original report. Withdrawn helper exclusion recommendations are ignored. It re-reads complete master/archive; existing canonical matches win over discovery closure. Original requests and identity holds are not replayed or force-matched. Prepared evidence remains available even when an item needs a different fact.

Use the common AI contract for the local environment and lock. local.cjs prepare --apply materializes the saved plan and closures; local.cjs step 100 submits one transaction and obtains original result, independent COMPLETE and exact later row effects. Repeat successive transactions, not the original request. local.cjs verify <requestId> reconciles a checkpoint after interruption. Persist all generated receipts/state before releasing the lock and rebase concurrent appends without force.

The canonical-positive guard disables any closure term newly matching applied/pursued-or-later canonical jobs. The observer publishes disabled term IDs in state/RELEVANCE_SCREEN_GUARD.json. On local prepare, closures made under a disabled term return to review with history preserved; canonical decisions are never resurrected. Existing historical backtest is a lower bound, not proof of zero future false negatives.

Native schedules and retired lanes remain unchanged. The active email/intake task reads the shared common instructions every run; no parallel owner or new AI automation is created.
