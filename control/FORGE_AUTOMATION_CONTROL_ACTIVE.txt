AUTOMATION PRODUCTION CONTRACT — UPDATED 2026-10-11
This section governs all five native Forge automations and any migrated app-managed worker. The shared Drive control is the source of truth; native automation prompts should remain thin TASK_KEY launchers that point here. Migration target: move schedules/workers without copying lane policy into platform-specific prompts.








A run is not successful because it fired, read rules, checked Writer, or updated last_run_time. A run is successful only when it produces lane output or proves a hard block. Every run must create or update one AI_REASON_RUN_RECEIPT in AI_Coordination before doing ambitious work, update it after each meaningful step, and finish by writing RUN_TERMINAL_STATUS. No terminal receipt is itself a failed run.








Allowed terminal statuses:
COMPLETE = minimum production requirement met, all submitted Writer work verified or explicitly no-write, carry-forward recorded.
PARTIAL_WITH_WORK = some useful lane output produced, minimum not fully met, exact unfinished work and next owner/action recorded.
HARD_BLOCKED = authority/tool/source gate prevented useful work; blocker is exact, non-optional, and next action is named.
FAILED_NO_WORK = automation fired but produced no useful lane output and did not prove a hard block.
FAILED = run encountered an error after partial setup or attempted work; exact failed step and next action recorded.








Minimum production requirements per run unless HARD_BLOCKED:
FORGE_EMAIL_DISCOVERY: open and disposition at least three real job-alert emails, or exhaust the eligible window with proof. For every opened email, preserve initiating URLs before filtering and record candidate-level disposition.
FORGE_WEB_CAREER_DISCOVERY: cover at least two target companies or ATS/company-search units and disposition all found candidates. Do not spend the run trapped on one company.
FORGE_ENRICH_STRATEGIC: research at least two exact eligible PRIMARY_IDs for strategic fit evidence, or prove no eligible IDs after live master/in-flight check.
FORGE_ENRICH_FEASIBILITY: resolve at least two exact pay/degree/FLEX/location/liveness gaps, or prove no eligible IDs after live master/in-flight check.
FORGE_APPLICATION_WRITER_GOFER: inspect and disposition at least two Writer/app exceptions, receipts, failed requests, identity collisions, or application-status obligations, or prove the explicit queues are empty.








Work-before-perfection rule: after authority, safety, freeze, and Writer-gate checks pass, perform one bounded production unit immediately before broad exploration. Do not spend the entire run on setup unless HARD_BLOCKED. If time is short, complete one useful unit and write PARTIAL_WITH_WORK rather than stopping silently.








Anti-spin rule: if the same blocker or same unresolved status appears for two consecutive runs, the lane must change method, shrink scope, route to the correct owner, or mark HARD_BLOCKED with exact next action. Repeating the same unresolved status without new action is FAILED_NO_WORK.








App-visible health expectation: Explorer/app health should treat FAILED_NO_WORK, missing terminal receipt, missing AI_REASON, no planned-vs-executed coverage, or stale carry-forward as health-impacting. Required visible fields are last run time, terminal status, planned work, executed work, records touched, Writer requests/receipts, carry-forward count, oldest unresolved item, blocker reason, next owner, and next action.








Native prompt posture: native automations should contain only provider, TASK_KEY, this control URL, requirement to fresh-read this document/rules/Writer/scoring, and requirement to obey the Automation Production Contract.
