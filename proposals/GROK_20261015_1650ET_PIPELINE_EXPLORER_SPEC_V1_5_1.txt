3.1 PERCENTILE POPULATION & BAND SNAPSHOT (v1.5.1; C#01, C#02, C#17, C#22, C#28)
  Population: eligible OPEN jobs (OPEN preset definition). Fixed — NEVER the current filter/view/search.
  Exclusions: STRICT FLEX / hard-blocked (shown ⊘ HOLD); applied, closed, declined, rejected,
    duplicates; unscored rows.
  Denominator N: population count at snapshot. Shown wherever bands are explained:
    "rank among N eligible open jobs · as of HH:MM".
  Rank: share of population strictly below + ½ ties. Band: >= P90 top · >= P65 upper · >= P20 mid · else low.
  Ties: equal scores always take the HIGHER band.
  Minimum N: if N < 40, bands hidden; numeric score only + "bands need >= 40 eligible open jobs (now N)".
  Out of population: applied/closed rows show numeric score + "— not ranked (applied|closed)"; HOLD rows
    show ⊘ HOLD; never a band colour.
  Snapshot (atomic): {modelRev, populationRev, N, cutP90, cutP65, cutP20, asOf} published together; all
    views (table, ring, pins, compare, phone) render from one snapshot id; swap in one frame.
  Refresh: on model publish, evidence change, population change; else at most once per 60 s.
  Tokens hold percentile RANKS (0.90 / 0.65 / 0.20). Score cut-points computed at runtime.
    Mock example only: N 412, cuts 61 / 54 / 38, top 76, median 48.
  Meaning: bands are RELATIVE rank. Numeric score (absolute), fit and ⊘ HOLD stay visibly separate;
    the top band is never labelled "good fit".
  Live counts: stale-evidence and all counts computed live with "as of HH:MM"; never hard-coded
    (185 of 603 was the 03:00 ET inventory snapshot only).

4.1 DECISIONS, SEEN-STATE, SHARED UNDO (v1.5.1; C#06, C#07, C#23)
  Decisions: receipt bound to record version seen at open + idempotency key. States waiting for lock ->
    writing -> CONFIRMED ONLY AFTER WRITER READBACK (never transport ack) | failed | superseded.
    Undo = verifiable inverse action on the confirmed state, receipted + read back. Decline writes only
    after a reason code. APPLIED / REJECTED_BY_EMPLOYER protection unchanged.
  Seen-state: no local-only option. Click is read-only; seen marks go to a debounced idempotent batch
    sync (e.g. 10 s or 20 marks), separate from decisions; visible status (✓ synced HH:MM / ◷ pending n /
    ⊗ failed · Retry) + repair (retry, re-read server). Server seen-state authoritative; merge by max
    timestamp so NEW markers match on phone and desktop.
  Shared-model Undo: restore previous revision's settings as a NEW revision sent with the CURRENT
    baseRevision; show current revision, exact field diff and any intervening publishes first; never
    roll back an intervening publish blindly. FACT (Code.gs scoringPublishConflict_): Writer rejects a
    publish with missing/stale baseRevision -> REVISION_CONFLICT; UI shows "revision N is now live —
    review diff".
