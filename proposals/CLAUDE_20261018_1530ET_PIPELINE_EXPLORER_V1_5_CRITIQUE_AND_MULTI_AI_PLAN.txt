0. BOTTOM LINE
-----------------------------------------------------------------------------------------------
- The direction is sound and the binding decisions hold together. The data-integrity-first phase order is right.
- The proposal cannot yet be built "exactly": the visual authority (v1.5 PDF) contradicts the v1.5.1 text in
  at least 9 places and contradicts ITSELF in at least 6 (section 3). An implementer copying the PDF would ship
  red Decline buttons, a Hold button wearing the Writer-lock glyph, bands on HOLD rows, a score breakdown that
  does not add up, and colour-only map pins.
- Exactness needs three things the proposal lacks: (a) one ruled conflict register, (b) approved golden frames
  rendered from one self-consistent fixture, (c) automated token / geometry / pixel / motion checks against
  those frames. Section 5 builds all three before any visual code.
- The live state-write defect from 2026-10-17 is still in main (FACT: Code.gs:171 and pipeline.html:956 unchanged).
  It stays first in line.

2.1 Where Grok Bot misread how the app works
N-01 FACT  Score breakdown does not match the scoring function. pipeline-scoring.js:67 scoreRow(): overall =
     round( (Σ w·s over KNOWN parts / Σ w over KNOWN parts) × (0.7 + 0.3 × coverage) ). Unknown parts drop out
     and lower confidence. PDF p40 drawer: parts sum to 31.5+24+10.5+9+4.5+3.8 = 83.3; header says "Σ 100% = 86";
     ring says 76. Three different numbers for one job. FIX: breakdown shows normalized contribution
     (w·s/Σw_known) plus a coverage line ("coverage 100% · factor 1.00") so points sum to the ring exactly.
     Mock numbers must be produced by scoreRow(), never typed.
N-02 FACT  "Writer is synchronous; queued = waiting for Writer lock" conflates two queues. Explorer posts go direct
     with busy retries (pipeline.html:754 gsPostRetryBusy_). Lane writes go through the Writer queue
     (Code.gs header: WRITER_QUEUE applied ~every minute; queue_stats). The mock change strip "2 queued" and
     KPI "Writer waiting/failed" mix both. FIX: two labelled counters — "◷ my decisions waiting for lock"
     and "lane queue N · oldest M min" (ties to CAND-01).
N-03 FACT  Per-decision Undo already exists (pipeline.html:1317 action undo_ruling; Code.gs action list).
     T-17 is written as new work. FIX: T-17 = wrap existing undo_ruling in the state machine + readback.
N-04 FACT  Current motion module auto-honours OS reduced motion (pipeline-motion.js: matchMedia
     prefers-reduced-motion). B-15 replaces that with a one-time prompt. Binding; flagging that this removes
     an existing behaviour. Keep ChatGPT 2055ET finding 02 (forced choice; re-prompt on OS change).
N-05 FACT  Fonts are not delivered. Tokens name Inter + IBM Plex Mono; the app loads neither (current stacks:
     -apple-system/Segoe UI and ui-monospace). On Tim's Windows PC "system-ui" renders Segoe UI.
     INFERENCE: glyph widths change, so column fits, truncation and line breaks will not match the mockup.
     FIX: self-host Inter + IBM Plex Mono (both SIL OFL) as woff2 with font-display:block for the HUD labels.
N-06 FACT  Mock data is not one dataset. Same jobs differ between views: Ridgeline VP Operations 61 TOP (p40)
     vs 57 UPPER (p42); Ironbark Plant Manager 58 vs 48; Vantor Head of Production 66 vs 63. Table claims
     "SORT: SCORE ↓" while rows run 35, 31, 67, 66…. Writer pill reads "WRITER IDLE" while KPI shows 1 waiting /
     1 failed. FIX: one fixture, scored by scoreRow(), used for every golden frame.

4. HOW EXACTNESS IS ENFORCED (the visual contract)
-----------------------------------------------------------------------------------------------
4.1 Authorities after rulings: (1) tokens.css — the only file with colour, size, duration, easing values;
    (2) golden frames — approved native-resolution PNGs per screen state; (3) geometry table — named element
    boxes per viewport; (4) spec v1.5.2 text for semantics and motion. Any disagreement is a defect in code.
4.2 Golden frames are built by rendering static HTML that uses tokens.css and the fixture, with the PDF v1.5 vector
    pages (SVG export) as the composition reference and section 3 rulings applied. Tim approves each frame by
    looking at it; approved frames are frozen in git (foreman-cockpit tests/visual/golden/).
    Frame list (desktop 2560×1440 @1x and @2x): F01 review queue default · F02 job selected (drawer + lock-on)
    · F03 map fullscreen · F04 decision waiting/confirmed/failed receipts · F05 scoring page · F06 geo map
    editing · F07 change strip + ticker states · F08 2048 (125 %) · F09 1707 (150 %).
    Mobile 402×874 @3x: M01 queue · M02 detail · M03 map + sheet · M04 landscape camera-left · M05 landscape
    camera-right · M06 desktop mode.
4.3 Automated checks on every PR (Playwright, existing harness pattern in tests/*.browser.js):
    a. Token check: computed style of ~60 named elements equals the token value exactly (colour, font-family,
       size, weight, letter-spacing, border, radius). Lint: no raw hex/duration/easing outside tokens.css.
    b. Geometry check: bounding boxes of zones, columns, tiles, buttons within ±1 CSS px per viewport;
       no horizontal scroll; tap targets clear of safe-area keep-outs.
    c. Pixel check: screenshot vs golden, fixture data, animations frozen at end state, fonts self-hosted;
       fail above 0.2 % differing pixels (threshold is an estimate; calibrate it on the first run).
    d. Motion check: document.getAnimations() duration/easing equal tokens; selection trace <= 700 ms p95
       over 50 selections; p95 frame <= 16.7 ms; <= 3 flashes/s.
4.4 Human checks: Tim on the real iPhone and the real 2560 monitor at each visual gate; Grok adversarial
    side-by-side review (golden vs build) and CVD/greyscale/low-light review at the Phase 3 gate.
