FINDINGS (numbered; severity / reference / evidence / proposed correction):
01. BLOCKER — HF-16 / §3 / token band cut-points. FACT: percentile labels and example score thresholds are supplied, but eligibility denominator, sample exclusions, refresh snapshot, tie-handling and minimum N are not defined. INFERENCE: a filter-dependent percentile makes a score change apparent when only a filter changes. FIX: rank one canonical fixed eligible OPEN, non-hard-blocked population (not the current filter), specify population/version/as-of and ties; publish all view bands from that snapshot. Historical/applied items get explicit out-of-population handling.
02. BLOCKER — §3 / HF-16 / CSS cut tokens. FACT: --pe-band-cut-top:61 / upper:54 / low:38 are example raw score values, even though dynamic percentile cutoffs are promised. FIX: encode percentile ranks P90/P65/P20 as policy constants; compute corresponding raw-score cutoffs from the canonical population at runtime; label examples mock-only. Handle ties explicitly.
03. BLOCKER — HF-15 / G7 / M-03,04,05,10. FACT: map fit 600ms and lock-on 320ms alone sum to 920ms when sequential; detail materialization and data loading are additional. FIX: execute non-dependent sequences concurrently or shorten fit to <=300ms and lock to <=240ms with bounded total; test selection end-to-end at p95, not animation duration only, including realistic 603+ records.
04. BLOCKER — HF-15 / M-15 / WCAG 2.2 SC 2.2.2. FACT: ticker at 40px/s auto-scrolls; hover/focus pause excludes touch and can be inaccessible to keyboard-only navigation unless a usable control exists. FIX: visible Pause/Resume and Hide or static mode, keyboard/screen-reader accessible; preserve reading position, honor reduced motion, avoid unnecessary autoplay.
05. BLOCKER — HF-15 / M-12 / SC 2.2.2. FACT: amber breathe at 1600ms repeats while waiting for lock, potentially >5s; toggle off by default means it animates automatically. FIX: always provide a global pause/reduce control and honor OS prefers-reduced-motion without requiring user setup; stationary amber status + textual seconds is equivalent.
06. BLOCKER — HF-03, T-17. FACT: one click starts irreversible-looking decision without Save, Undo is promised. INFERENCE: race/timeout or stale record may leave user uncertain whether Undo is safe. FIX: receipt bound to record version/idempotency key and a verifiable inverse action; on server-confirmed state transitions only; display pending and failed independently; never report success on mere transport ack. For declined reason selection, one click can start only after required reason is available.
07. BLOCKER — HF-04 / T-06 vs current state. FACT: current openRow writes seen-state and the proposal alternates local-only and batched-explicit receipt. INFERENCE: local-only loses cross-device NEW marker coherence. FIX: make opening a job visually read-only immediately but enqueue a debounced idempotent seen-state sync, with explicit sync status/error repair, separate from application/disposition transactions. Offline local fallback must be clearly designated.
08. BLOCKER — HF-15 / M-01..M-19 / accessibility. FACT: Reduce-motion is a LOCAL toggle OFF by default, and token CSS only sets breathe 0ms and fit 120ms; the remainder of the catalog lacks complete substitutions. FIX: OS preference wins by default, with optional explicit override; create per-M motion-reduced equivalents including scanline/pixel dissolve, rolling digits, infinite ticker, wipe, reticle rotation, shimmer/sweep, map pan/zoom, swipe springs, and boot sequence. Enforce no essential information delay.
09. SHOULD-FIX — §3 / palette semantics / WCAG 1.4.1. FACT: green = Pursue/confirmed/top, amber = upper band/Hold/wait/SHARED, olive = stale/unverified, red = failure/block; so 'one colour = one meaning' is false. FIX: semantics are compound: colour + unique glyph + explicit word + location; document this instead of promising one-to-one hues; no success/failure or percentile information conveyed solely by hue.
10. SHOULD-FIX — §11.6 / tokens; colour vision. FACT: Clay #D9826B contrasts ~7.36:1 on black and 6.45:1 on Plate; Alert Red #FF4D3D ~6.38:1 / 5.60:1; Amber #F2B33D ~11.29:1 / 9.91:1. These are background-contrast measures, NOT pairwise hue discriminability. INFERENCE: Clay vs red may look similar under altered color vision, and amber vs Clay can overlap in poor conditions. FIX: retain user-approved colours, but require glyph + 'LOW'/'HOLD'/'UPPER' words in table and map popovers; simulate protan/deutan/tritan, grayscale and low-light screenshots before signoff.
11. SHOULD-FIX — §2, tokens contrast / SC 1.4.3, 1.4.11. FACT: Terminal Grey #5A5A5A contrast black 3.04:1, Plate 2.67:1; Gridline #3A3A3A on Plate ~1.62:1. Muted #6B6B66 on Plate 3.44:1; only lawful for genuinely large 3:1 text, not small. FIX: make meaningful non-text 3:1+ against adjacent Plate; do not rely on Seams/Gridline for sole control boundaries; 11px headers and 9.5px ◌ must not use Muted; test actual alpha composites, hover overlays, and selected states.
12. SHOULD-FIX — HF-15 / M-08/12/19 / SC 2.3.1. FACT: <=3 flashes per second budget is specified, but multiple components can flash concurrently; a flashing event can differ from an ordinary brightness pulse. FIX: test combined screen capture for general and red-flash thresholds, not just per-widget counts; stagger/disable multiple pulses and scanlines, especially failure shake and rapid changes. A slow amber breath does not automatically violate 2.3.1, but can still violate 2.2.2 or distract.
13. SHOULD-FIX — HF-06/07/18, §3 / SC 2.4.7, 2.4.11. FACT: token 'glow only on focus' and 1px trace does not guarantee visible focus; map/fullscreen/slide motions may occlude focus. FIX: strong high-contrast persistent focus indicator, not glow-only, all keyboard interactive surfaces including glyph actions, chart controls, swipes alternatives; prevent sticky overlays obscuring focus and preserve focus on closing drawers.
14. SHOULD-FIX — HF-07/13/18 / SC 2.5.8. FACT: desktop 11.5px button labels, 32px rows and narrow table action icons coexist; mobile target minimum 44pt proposed, whereas 2.5.8 baseline is 24x24 CSS px (with spacing/exceptions), not 44pt; touch preference appropriately exceeds minimum. FIX: audit actual hit rectangles and inter-target spacing on every icon and checkbox at desktop/phone zoom, ensure 24px minimum or valid spacing exception for desktop and 44pt preferred for mobile; prevent hidden overlap.
15. SHOULD-FIX — HF-06/18 / keyboard order. FACT: sliding rail, fixed map, tab bar, layered settings, mobile sheet and fullscreen overlay create focus-order risks; Escape close is specified, but no complete focus-order contract. FIX: define DOM/tab order rail > queue > map > workspace (or user task path); selection returns focus predictably; modal map traps only if genuinely modal, closes with Escape and restores focus, never traps user, and menu/layers controls have keyboard equivalents.
16. SHOULD-FIX — HF-03 / T-17 / glyph system. FACT: ✕ close, ⊖ decline, ⊗ failure, ⊘ block, ▽ bottom band are unique glyphs but are abstract and small. INFERENCE: similar circular marks have poor recognition under dense scanning and on mobile. FIX: glyphs never stand alone on first exposure or decision controls; always accessible name and visible verb on primary decisions, compact legend/help and consistent positioning; record confusion and misclicks in the timed usability baseline.
17. SHOULD-FIX — HF-16 / percentile bands. FACT: top 10/next 25/mid 45/bottom 20 partitions display rank, not absolute suitability; if most jobs are weak, top 10 is still green. FIX: explain 'relative rank among eligible open jobs' wherever bands are taught; keep hard eligibility/STRICT and absolute numeric fit visibly distinct; never label TOP as objectively 'good fit' without an independent threshold. Display rank population N and as-of.
18. SHOULD-FIX — HF-10 / M-08/15 / attention. FACT: change strip plus 40px/s ticker plus row wipe plus KPI roll-ups can compete simultaneously. FIX: change strip is operator-primary with clickable grouped counts/causes; ticker is optional, paused by default or low-noise, with deduplication/burst throttles, muted bot events, and no automatic forced attention while deciding. Test time-to-decision against no-ticker baseline.
19. SHOULD-FIX — HF-17 / 2560 layout. FACT: columns 56+1112+800+508=2476; margins 2x20 plus three nominal gutters 3x16 =2564, exceeding 2560 by 4px (before borders). Token notes 12px rail gap, which would bring nominal total to 2560 exactly, with no allowance for other borders. FIX: define a single measured grid equation including the 12px rail gap, borders, scrollbar, DPI scaling and OS zoom; fractional tracks/minmax and no clipping; test at 100%, 125%, 150%.
20. SHOULD-FIX — HF-18 / mobile. FACT: iPhone dimensions labelled ASSUMED, use env insets and side padding; tokens use CSS 'pt' custom properties and desktop-mode switch bypasses viewport context; camera keep-out hatch appears red as special overlay. FIX: derive live safe areas and orientation, test simulator + real-device both landscape rotations + desktop mode; do not implement speculative model-specific hardcoded cutouts. Treat mockup hatch colors as documentation, never runtime urgency signaling.
21. SHOULD-FIX — §5 / map targeting tokens vs B-04. FACT: target map includes reticle circle r22 and outer dashed ring r31, though B-04 says no 'range rings' and M-06 prohibits ping rings. INFERENCE: visually these may be interpreted as forbidden range/radar rings. FIX: explicitly classify reticle concentric markers as non-ranging aiming indicia, or replace circular ring(s) with brackets/ticks only; no sweeping/expanding rings and no numeric range encoded by radius. Tim's targeting aesthetic is preserved.
22. SHOULD-FIX — §11.6 / token score cuts vs display-only. FACT: band recomputation on 'model or eligible population' change, but no snapshot/version transaction boundary exists. FIX: atomic publish of modelRev+populationRev+cutoffs and render snapshots consistently; avoid stale split views and order-of-arrival flashes after filter/rank changes.
23. SHOULD-FIX — HF-19 / impact preview / undo. FACT: shared publish confirmation and impact counts are promised, but 'Undo' republishes prior revision; concurrent operator changes could occur between receipt and Undo. FIX: compare-and-swap revision precondition, show exact diff and current revision before restore, disallow blind rollback of intervening edits. An undo is a new publish, not deletion of history.
24. SHOULD-FIX — HF-15 / M-09 / p95. FACT: 18ms x 30 row staggers yields 522ms offset and trailing duration on top; may visually imply re-ranking while rows still materialize. FIX: keep data rows hit-testable and final ordering fixed from frame 1; cap stagger span <=250ms on selection and disable under bursts/large filtered sets.
25. MINOR — PDF §13.1. FACT: reviewer reports residual '82 ✓ STRONG' hover card inconsistent with percentile band vocabulary; extracted PDF text supports section exists but visual residual not independently verified from a rendered page. FIX: manually inspect PDF page 33 and replace any fixed score adjective with ▲/◆/●/▽ band + rank context; do not ship contradictory visual references.
26. MINOR — §4/§7 / M-07. FACT: numbers roll 800ms while true value exists in DOM. INFERENCE: sighted user may read an intermediate value and misinterpret a count. FIX: render final stable value beside or over the decorative animation; accessibility announcement only on meaningful final changes, not every frame.
27. MINOR — token consistency. FACT: signal bar is 2px in token and 3px on cards in mockups; token typography 10.5–11px field labels and 11px buttons should not be assumed accessible by nominal contrast alone. FIX: express 3px card variant as explicit token and validate readability at normal working distance.
28. MINOR — HF-19 / T-02. FACT: '185/603 stale stored evidence' is a point-in-time snapshot. FIX: compute live denominators and timestamp; do not hardcode this number in KPI, settings, or acceptance.
29. MINOR — §7 / M-14. FACT: 1px cyan hover trace animation is hover-only. FIX: support keyboard focus and touch pressed/selected equivalents, with a more legible static focus cue.

MOTION EXCEPTION COVERAGE:
The available v1.1 rationale explicitly admits cinematic movement with concrete purpose but does not issue blanket automatic approval for all M-01..19. M-01,02,04,05,06,08,11,12,13,14,16,17,18,19 have plausible attention/state/relationship mechanisms when controlled. M-03 pixel dissolve, M-07 numeric rolling, M-09 repeated staggers, M-10 score ring, M-15 ambient ticker have elevated attention/latency cost and require measured benefit or user opt-out. All 19 require full accessible reduced-motion fallbacks; G1-G7 are constraints, not a waiver. No permanent doctrine amendment recommended: defects are specification and verification items; purported v1.2 exception remains unverified.

FINAL ASSESSMENT (OPINION): DO NOT IMPLEMENT v1.5 AS WRITTEN. Approve direction only; clear BLOCKERS 01–08, retest AA with live interactions, settle precise map-ring semantics, and conduct Tim phase gates. Keep dense table, permanent center map, targeting identity, rich purposeful motion, independent mobile, black/grey HUD, one-button readback, and display-only percentile bands unchanged.
