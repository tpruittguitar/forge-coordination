LANE PROCEDURE -- FORGE_POSTING_VALIDATION

JOB
Background maintenance: check aging active postings and record what the page shows. No scoring, no deep job-description analysis, no apps, no contacting anyone.

BACKGROUND POSTING FRESHNESS — Tim 2026-10-31
This task is outside the main pipeline. It never gates enrichment, review readiness or the main-line constraint calculation.
Select ACTIVE, unprotected jobs across all active buckets only after seven days from a reliable POSTING_DATE/POSTED_DATE; otherwise seven days from first discovery (DISCOVERED_AT_ET, DATE_ADDED, MASTER_LOADED_AT, earliest reliable date). No reliable date: flag UNDated for evidence review, do not invent an age or continually retry it. Reuse a saved successful posting check for seven days; unclear/blocked attempts retry no sooner than 24 hours. Never read a young posting merely because LIVENESS is missing.
Use the current Writer-generated WORKLIST_FORGE_POSTING_VALIDATION when under six hours old; the shared PipelinePostingFreshness.assess rule also controls the automatic ATS checker. If it is stale, select from fresh master with the same age rule; never fall back to the former SCOUT_INTAKE-only missing-LIVENESS gate. Prefer employer ATS APIs when supported; preserve current ATS ownership and avoid duplicate pending writes. Honor Writer freeze and shared run lock.
Never touch APPLIED, REJECTED_BY_EMPLOYER, DECLINED_BY_TIM, DUPLICATE, CLOSED_DEAD, anti-resurrection rows or saved Tim rulings. Before claiming a row, skip anything in the Writer queue or a recent RESULT. Existing fresh discovery/intake evidence that already establishes liveness is reused; no repeat page fetch for a current check.

HOW TO CHECK A ROW
- Use TinyFish fetch_content (free) when available: up to 10 URLs per call, ttl 0, per_url_timeout_ms 60000. Never run_web_automation, browser sessions or monitors; never sign in, apply, submit a form or attempt a CAPTCHA.
- Employer ATS or careers page open = LIVE_EMPLOYER_ATS. Workday: a page with the title and "job requisition id" = open; "The page you are looking for doesn't exist" on a URL ending in the requisition token (_R12345, _REQ-12345, _JR12345) = CLOSED; on a URL w/o the token, search the site (https://<host>/<site>?q=<title words>, links=true) and fetch the matching job link.
- LinkedIn job page (https://www.linkedin.com/jobs/view/<id>) with a posted age and no closed notice = LIVE_SECONDARY, LIVENESS_NOTE "LinkedIn page, posted <age>, read <date>". "No longer accepting apps" = CLOSED for a row whose only source is that LinkedIn post.
- Indeed blocks TinyFish: find the employer post by exact co, title, loc and requisition ID instead.
- Apply the shared agy/source rules above. If a source blocks, try the employer route; w/o qualifying evid use UNCONFIRMED and record attempts.
- Record REQ_ID, pay, loc, work arrangement and post date only when the page shows them, verbatim.
