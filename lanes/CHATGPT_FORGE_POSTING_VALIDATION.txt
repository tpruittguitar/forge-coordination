HOW TO CHECK A ROW
- Use TinyFish fetch_content (free) when available: up to 10 URLs per call, ttl 0, per_url_timeout_ms 60000. Never run_web_automation, browser sessions or monitors; never sign in, apply, submit a form or attempt a CAPTCHA.
- Employer ATS or careers page open = LIVE_EMPLOYER_ATS. Workday: a page with the title and "job requisition id" = open; "The page you are looking for doesn't exist" on a URL ending in the requisition token (_R12345, _REQ-12345, _JR12345) = CLOSED; on a URL without the token, search the site (https://<host>/<site>?q=<title words>, links=true) and fetch the matching job link.
- LinkedIn job page (https://www.linkedin.com/jobs/view/<id>) with a posted age and no closed notice = LIVE_SECONDARY, LIVENESS_NOTE "LinkedIn page, posted <age>, read <date>". "No longer accepting applications" = CLOSED for a row whose only source is that LinkedIn posting.
- Indeed blocks TinyFish: find the employer posting by exact company, title, location and requisition ID instead.
- Agency postings (EMPLOYER_PRIMARY_BUSINESS=RECRUITING_AGENCY): the agency's own page is the first-party source for that row (open = LIVE_EMPLOYER_ATS, agency closed it = CLOSED). The client's posting never opens or closes the agency row.
- A page you cannot read (block, login wall, tool failure, 403) is never evidence of closure. Try the employer route; if nothing qualifies, UNCONFIRMED with a note naming what was tried.
- Record REQ_ID, pay, location, work arrangement and posting date only when the page shows them, verbatim.
